# 육아휴직 잔여기간 계산기 — 산식 문서

> 다른 프로그램에서 동일한 계산 로직을 재구현할 때 참고하는 스펙 문서입니다.
> 원본 구현: `sonsa-mom` 리포지토리 `calculator.html`의 육아휴직 계산기(`Parental` 모듈).
> 실제 노동부/고용보험 기준과 오차가 있을 수 있는 **참고용 로직**이며, 법적 정확성은 별도 검증이 필요합니다.

---

## 1. 무엇을 계산하는가

육아휴직을 여러 번(최대 9회차)에 나눠 쓴 이력을 입력하면,

1. 각 회차별 사용기간을 "개월 + 일" 단위로 정밀 계산하고
2. 전체 회차를 합산해 **총 사용기간**(개월, 소수점 포함)을 구하고
3. 법정 최대 한도(배우자 육아휴직 사용 여부에 따라 12개월 또는 18개월)에서 총 사용기간을 뺀 **잔여기간**을 구하고
4. (선택) 잔여기간을 특정 시작일부터 이어 쓴다고 가정했을 때 **예상 종료일**을 계산한다.

핵심은 "개월"이라는 단위를 **엑셀 `DATEDIF` 함수 방식**으로 정의한다는 점이다 — 달력상의 개월수 + 나머지 일수를 해당 월의 총 일수로 나눈 소수로 표현한다. 단순히 `(종료일-시작일)/30` 같은 근사 계산을 쓰지 않는다.

---

## 2. 입력

| 항목 | 설명 |
|---|---|
| `spouseUsed` | 배우자가 육아휴직을 3개월 이상 사용했는지 여부 (boolean) |
| `periods[]` | `{start, end}` 형태의 회차별 사용기간 배열 (최대 9개, 비어있는 회차는 무시) |
| `expectedStart` | (선택) 잔여기간 모의계산용 예상 시작일 |

날짜는 모두 `YYYY-MM-DD` 문자열.

---

## 3. 최대 사용기간 규칙

```
maxMonths = spouseUsed ? 18 : 12
```

- 기본 12개월
- 배우자가 3개월 이상 육아휴직을 사용한 경우 본인 몫이 6개월 늘어나 **18개월**
  (2025년 이후 "6+6 부모육아휴직제" 등 개정을 단순화해 반영한 값. 실제 법정 요건은 별도 확인 필요)

---

## 4. 회차별 "개월 + 일" 계산 — `calcMonthsAndDays(start, end)`

### 4.1 의도

엑셀에서 `=DATEDIF(시작일, 종료일+1, "m")` (완전한 개월수)와 `=DATEDIF(시작일, 종료일+1, "md")` (개월을 채우고 남는 일수)를 조합해 쓰는 방식과 동일하다. 종료일을 하루 뒤로 밀어서(`+1`) **시작일과 종료일을 모두 포함하는** 기간으로 취급하는 것이 포인트다 (예: `2026-01-01 ~ 2026-01-31`은 "1개월"이어야 하고, 실제로 `end+1 = 2026-02-01`이므로 정확히 1개월 차이가 난다).

### 4.2 절차

1. `end = end + 1일` (엑셀 DATEDIF의 "종료일 다음날" 트릭)
2. `end <= start`면 계산 불가(`null`) — 즉 원래 종료일이 시작일보다 빠른 경우
3. **개월수(`months`)**: 연도차×12 + 월차로 먼저 어림잡고, `start`에 그 개월수를 더한 날짜(`t1`)가 `end`를 넘으면 1개월 차감해 보정한다 (예: 시작일이 31일인데 다음 달이 30일까지밖에 없는 경우 등 월말 보정)
4. **나머지 일수(`remainDays`)**: `start + months`한 날짜(`t2`)부터 `end`까지 며칠 남는지 (밀리초 차이를 86400000으로 나눠 반올림)
5. **분모(`daysInMonth`)**: `end`가 속한 달의 총 일수 (그 달의 마지막 날짜)
6. **소수 변환(`fraction`)**: `remainDays / daysInMonth`를 소수점 3자리에서 **버림**
7. **합계(`total`)**: `months + fraction`을 다시 소수점 3자리에서 **버림**

### 4.3 의사코드

```
function calcMonthsAndDays(start, end):
    if start or end is empty: return null
    end = end + 1 day                              # DATEDIF 트릭
    if end <= start: return null                    # 종료일이 시작일보다 빠름

    months = (end.year - start.year) * 12 + (end.month - start.month)
    t1 = start + months (개월 단위로 더함)
    if t1 > end:
        months -= 1                                  # 월말 보정

    t2 = start + months
    remainDays = round((end - t2) in days)
    if remainDays < 0: remainDays = 0

    daysInMonth = end가 속한 달의 마지막 날짜(28~31)
    fraction = floor(remainDays / daysInMonth * 1000) / 1000   # 소수 3자리 버림
    total   = floor((months + fraction) * 1000) / 1000         # 소수 3자리 버림

    return { months, remainDays, daysInMonth, fraction, total }
```

### 4.4 실제 구현 (JavaScript, 원본 그대로)

```js
function calcMonthsAndDays(startStr, endStr) {
  if (!startStr || !endStr) return null;
  const start = new Date(startStr + 'T00:00:00');   // 로컬 자정으로 파싱 (타임존 안전)
  const end = new Date(endStr + 'T00:00:00');
  end.setDate(end.getDate() + 1);
  if (end <= start) return null;

  let months = (end.getFullYear() - start.getFullYear()) * 12
             + (end.getMonth() - start.getMonth());
  const t1 = new Date(start);
  t1.setMonth(t1.getMonth() + months);
  if (t1 > end) months -= 1;

  const t2 = new Date(start);
  t2.setMonth(t2.getMonth() + months);
  let remainDays = Math.round((end - t2) / 86400000);
  if (remainDays < 0) remainDays = 0;

  const daysInMonth = new Date(end.getFullYear(), end.getMonth() + 1, 0).getDate();
  const fraction = Math.floor((remainDays / daysInMonth) * 1000) / 1000;
  const total = Math.floor((months + fraction) * 1000) / 1000;

  return { months, remainDays, daysInMonth, fraction, total };
}
```

> **타임존 주의**: 날짜 문자열을 `new Date('2026-08-24')`처럼 그대로 넘기면 UTC 자정으로 해석되어, UTC보다 느린 타임존(미국 등)에서는 하루가 밀릴 수 있다. 반드시 `new Date(str + 'T00:00:00')`처럼 **로컬 자정**으로 파싱할 것. 결과를 다시 문자열로 만들 때도 `toISOString()`(UTC 변환) 대신 `getFullYear/getMonth/getDate`로 직접 조립해야 안전하다.

## 5. 총 사용기간 / 잔여기간

```
calcResults = periods.map(p => calcMonthsAndDays(p.start, p.end))   # null 포함 가능

totalUsed = sum(r.total for r in calcResults if r is not null)
remaining = max(0, maxMonths - totalUsed)
isOver    = totalUsed > maxMonths
```

- `totalUsed`, `remaining`은 소수점 3자리까지 의미 있는 개월 단위 실수
- `isOver`가 true면 법정 한도 초과 (UI에서 경고 표시)

## 6. 예상 종료일 — `calcEndDate(start, remainMonths)`

잔여기간(`remainMonths`, 개월 단위 소수)을 특정 시작일부터 이어 쓴다면 언제 끝나는지 계산한다. 노동부가 실무에서 쓰는 방식(정수 개월은 달력으로 이동, 소수 부분은 "그 도착한 달의 일수" 기준으로 일수 환산)을 따른다.

### 6.1 절차

1. `remainMonths`를 정수부(`fullMonths`)와 소수부(`fraction`)로 분리
2. `start`에 `fullMonths`만큼 달을 더한 날짜(`q`) 계산 — 예: 1/15 시작 + 2개월 → 3/15
3. `q`가 속한 달의 총 일수(`daysInMonth`)로 소수부를 일수로 환산: `extraDays = floor(fraction * daysInMonth)`
4. 최종 종료일 = `q - 1일 + extraDays`
   - `-1일`을 하는 이유: "시작일 포함 N개월"의 마지막 날은 달을 다 채운 날짜의 **전날**이기 때문 (예: 1/1부터 1개월이면 마지막 날은 1/31이지 2/1이 아님)

### 6.2 의사코드

```
function calcEndDate(start, remainMonths):
    if remainMonths <= 0: return null

    fullMonths = floor(remainMonths)
    fraction   = remainMonths - fullMonths

    q = start + fullMonths (개월 단위)
    daysInMonth = q가 속한 달의 마지막 날짜
    extraDays = floor(fraction * daysInMonth)

    end = q - 1일 + extraDays
    return end
```

### 6.3 실제 구현 (JavaScript, 원본 그대로)

```js
function calcEndDate(startStr, remainMonths) {
  if (!startStr || remainMonths <= 0) return null;
  const start = new Date(startStr + 'T00:00:00');

  const fullMonths = Math.floor(remainMonths);
  const fraction = remainMonths - fullMonths;

  const q = new Date(start);
  q.setMonth(q.getMonth() + fullMonths);

  const daysInMonth = new Date(q.getFullYear(), q.getMonth() + 1, 0).getDate();
  const extraDays = Math.floor(fraction * daysInMonth);

  q.setDate(q.getDate() - 1 + extraDays);
  return toLocalISODate(q);   // getFullYear/getMonth/getDate로 직접 조립 (UTC 변환 금지)
}
```

## 7. 검증된 예시 (직접 실행해서 확인한 값)

### 예시 A — 정확히 6개월
```
calcMonthsAndDays('2026-01-01', '2026-06-30')
→ { months: 6, remainDays: 0, daysInMonth: 31, fraction: 0, total: 6 }
```
1/1~6/30은 "정확히" 6개월(1월~6월 전체)이라 나머지 일수가 0이 되는 게 맞음.

### 예시 B — 개월 + 나머지 일수
```
calcMonthsAndDays('2026-01-15', '2026-07-10')
→ { months: 5, remainDays: 26, daysInMonth: 31, fraction: 0.838, total: 5.838 }
```
1/15~6/15가 5개월, 거기서 7/10까지 26일 남음. 7월은 31일이라 26/31 ≈ 0.839를 소수 3자리로 버림하면 0.838. 5 + 0.838 = 5.838개월.

### 예시 C — 2회차 합산 후 잔여기간·예상 종료일
```
1회차: 2026-01-01 ~ 2026-04-30 → total = 4
2회차: 2026-07-01 ~ 2026-08-15 → total = 1.483
totalUsed = 5.483
maxMonths = 12 (배우자 미사용)
remaining = 12 - 5.483 = 6.517

calcEndDate('2026-09-01', 6.517) → '2027-03-16'
```

### 예시 D — 정수 개월의 종료일 (월말 경계 확인)
```
calcEndDate('2026-01-01', 3) → '2026-03-31'
```
1/1부터 "만 3개월"의 마지막 날은 4/1의 전날인 3/31이 되는 게 맞음 (2월이 28일이라도 개월 단위 이동은 `setMonth`로 처리되므로 안전).

## 8. 알려진 한계 / 주의사항

- **참고용 계산기**: 실제 회사 급여 시스템·고용24 판정과 오차가 있을 수 있음을 반드시 사용자에게 고지할 것.
- **분할 횟수 제한 미검증**: 이 계산기는 입력한 기간의 총합만 계산할 뿐, "법정 3회 분할" 같은 횟수 제한은 강제하지 않음 (참고 계산용이라 회차 수를 넉넉히 9개까지 열어둠).
- **월말 보정**: `setMonth()` 기반 개월 이동은 JS/Excel 모두 "말일 넘침"을 자동으로 다음 달로 안 넘기고 보정하는 방식이 다를 수 있어, 이식 시 반드시 4.3의 `t1 > end` 보정 로직을 그대로 유지해야 함.
- **타임존**: 반드시 로컬 자정 파싱 + 수동 날짜 조립(`toLocalISODate`)을 쓸 것. `new Date(str)` 단독 파싱이나 `toISOString()` 단독 출력은 UTC 변환 과정에서 하루가 밀리는 버그를 만들 수 있음 (한국 표준시(UTC+9)에서는 우연히 상쇄되어 안 드러날 수도 있지만, 다른 타임존에서 재사용하면 바로 문제가 됨).
